# 后台控制可行性实验（background-control）

状态：Phase 1 实验方案（2026-11-17），**尚未执行，结果为空**。
纪律：禁止伪造测试数据、模拟成功结果或把未完成功能标记为完成。所有结果必须来自 `src/probe/run_experiments.py` 的可复跑输出。

## 1. 目标

验证 Windows 上“不移动物理鼠标/键盘的后台语义操作”在哪些条件下成立，并明确哪些应用/操作不支持后台操作。对应任务书第一阶段验收：

1. 至少一个应用支持不移动物理鼠标的语义操作。
2. 能记录焦点变化事件。
3. 能检测目标控件操作是否成功。
4. 能明确识别不支持后台操作的情况。
5. Trae 实际支持能力有测试证据。
6. 所有实验可重复运行。

## 3. 实验矩阵

| ID | 实验 | 目标 | 方法 | 预期证据 |
|---|---|---|---|---|
| E1 | 原生 UIA pattern | 证明不移动物理鼠标可操作控件 | ctypes Win32 靶应用（按钮/输入框/复选框/状态）；Invoke / SetValue / Toggle；操作前后读状态 | 控件状态变化 + 光标位置不变 + 前台 HWND 不变 |
| E2 | FocusGuard 检出 | 证明能记录焦点变化 | 动作前后快照 + `EVENT_SYSTEM_FOREGROUND`；注入已知焦点切换作为正例 | 焦点事件序列 + 检出/漏检统计 |
| E3 | UIA vs SendInput | 对比语义操作与前台输入 | 同一控件分别走 UIA 与 SendInput；记录成功率、焦点切换、光标位移 | 四态 ActionResult 分布 |
| E4 | 几何变化 | 遮挡/移动/缩放/DPI 下的行为 | UIA pattern 调用 vs 坐标点击；改变窗口几何后重复 | 成功率对比；坐标法失效证据 |
| E5 | 能力扫描与负例 | 明确不支持后台的情况 | 扫描原生靶应用、Notepad/Calculator、Trae、微信 4.x；记录通道与原因 | `unsupported_reason`（如 UIA 无节点、忽略窗口消息） |
| E6 | Trae 能力复跑 | 刷新 AI IDE 证据 | 复用 `src/probe/cdp_*.mjs` 与 `uia_probe.py`；只读/固定无害消息 | 更新 `src/probe/PROBE_REPORT.md` 增补节 |

## 4. 指标

| 指标 | 定义 |
|---|---|
| 操作成功率 | 后置条件（控件状态/文本/业务状态）达成比例 |
| 效果验证率 | 有独立读回证据的比例 |
| 焦点切换次数 | 动作窗口内前台 HWND 变化次数 |
| 光标位移 | 动作前后 `GetCursorPos` 距离 |
| 干扰四态分布 | 成功无干扰观察 / 成功但干扰 / 失败 / 无法确认 |
| 负例识别率 | 正确返回“不支持后台”的应用×操作比例 |
| 漏检率 | 注入焦点切换但未记录的比例（E2） |

## 5. 执行流程

1. 启动靶应用；记录窗口句柄与控件树（只读）。
2. 运行 E1：UIA pattern 操作 + 状态回读；FocusGuard 包裹。
3. 运行 E2：注入焦点切换正例，统计检出。
4. 运行 E3：同一操作走 SendInput 基线；对比四态与光标/焦点。
5. 运行 E4：改变窗口几何后重复 E1/E3。
6. 运行 E5：能力扫描，写入 `var/experiments/capability.json`。
7. 运行 E6：Trae 探针复跑（遵守 live 安全约束）。
8. 汇总原始 JSON → 在本文第 7 节填写真实结果。

## 8. 判定标准

- 验收 1：E1 至少一个原生控件在光标零位移、前台不变的情况下完成操作并读回状态。
- 验收 2：E2 能输出焦点事件序列，并给出正例检出结果。
- 验收 3：E1/E3 的后置条件由独立读回验证，不能以调用无异常作为成功。
- 验收 4：E5 对至少一个不支持后台的目标给出可复核的 `unsupported_reason`。
- 验收 5：E6 更新 Trae 证据（F1–F12 可复跑）。
- 验收 6：同一命令在记录环境下可重复得到一致结论（允许环境差异，需注明）。

## 9. 已知限制

- `SUCCESS_NO_INTERFERENCE_OBSERVED` 仅表示监测窗口内未观察到干扰，不等于绝对无干扰。
- OCR 只提供定位，不提供后台输入能力；OCR + 前台输入仍属 `PHYSICAL_INPUT`。
- 微信 4.x 自绘界面：UIA 无控件语义、窗口消息不可靠；这是负例，不是待修复缺陷。
- FocusGuard 采样可能漏检瞬时焦点切换；需报告漏检率。
- live Trae 实验受“仅 chat、手动审批”安全约束；agent 模式验证需用户显式授权。
